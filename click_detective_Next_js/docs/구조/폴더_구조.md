# 폴더 구조와 수정 기준

화면과 그 화면에 필요한 보조 코드를 같은 기능 폴더에 둡니다. 프런트엔드의 책임에 맞게 증거·심문·메모·추론 등을 나눴습니다.

```text
click_detective_Next_js/
├── app/                         Next.js 진입점·주소·CSS
│   ├── page.tsx                 첫 화면
│   ├── layout.tsx               공통 HTML 틀
│   ├── api/detective/[...segments]/route.ts
│   ├── assets/[...asset]/route.ts
│   ├── manor.jpg/route.ts
│   └── styles/                  기존 CSS와 순서대로 나눈 하위 파일
├── features/
│   ├── application/             앱 조립·메뉴·공통 팝업
│   ├── catalog/                 공개 사건 자료·홈·사건 선택·오프닝
│   ├── investigation/           수사 상태·행동 요청·복원·표시 보조
│   ├── materials/               증거 목록·문서 팝업·화면 조회
```

## 파일을 나누는 기준

- 화면은 각 `*-screen.tsx`가 그리고, 공통 조립은 `CaseApp`과 `InvestigationWorkspace`가 합니다.
- `useCaseGame`은 화면 상태와 사용자 행동을 연결합니다. 복원·메모 저장·팝업 효과는 별도 훅입니다.
- `game-client.ts`는 요청 순서와 실패 복구를 처리하고, `commands.ts`는 행동 이름·필드를 바꿉니다.
- 서버에서는 `policy.ts`가 허용 경로, `request.ts`가 입력, `responses.ts`가 출력, `handle.ts`가 전체 순서를 맡습니다.
- 새 코드는 실제 구현이 있는 `features`, `shared`, `server`에서 수정합니다. 이전 `components`, `hooks`, `lib` 경로는 호환용입니다.

소스 파일은 주석을 포함하여 250줄 이내입니다. 이름 있는 함수·클래스는 JSDoc에 역할·입력·반환값을 적습니다. 무명 `map` 콜백이나 이벤트 콜백은 가까운 코드에서 읽도록 두며, 별도 이름을 붙인 도우미는 설명을 작성합니다. `npm test`가 줄 수와 설명 누락을 확인합니다. 자동 생성 잠금 파일과 JSON 검사 자료는 소스 줄 수 대상에서 제외합니다.

## CSS 파일이 여러 개인 이유

큰 스타일 파일은 기존 규칙 순서를 지키며 `home/`, `investigation/`, `responsive/`의 `part-XX.css`로 나눴습니다. 상위 CSS의 `@import` 순서가 적용 순서입니다. 같은 선택자가 뒤에서 다시 나타날 수 있으므로 파일을 이름순으로 임의 합치거나 규칙을 옮기지 마세요. CSS 회귀 검사는 679개 규칙의 선택자·조건·속성·순서를 확인합니다.

[함수별 설명](../코드참조/README.md)에서 각 파일의 실제 선언을 볼 수 있습니다.
