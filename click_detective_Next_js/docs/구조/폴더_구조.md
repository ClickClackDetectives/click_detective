# 폴더 구조와 수정 기준

`app/game/`에는 게임 상태·요청·훅·타입을, 루트 `components/`에는 실제 화면과 팝업을 둡니다. CSS는 루트 `styles/`로 분리합니다. 각 영역 안에서는 증거·심문·메모·고발처럼 기능별로 묶습니다. `app/game`의 일반 함수·훅 파일은 `page.tsx`나 `route.ts`가 아니므로 별도 페이지 주소를 만들지 않습니다.

## 파일을 나누는 기준

- 화면은 각 `*-screen.tsx`가 그리고, 공통 조립은 `CaseApp`과 `InvestigationWorkspace`가 합니다.
- `useCaseGame`은 화면 상태와 사용자 행동을 연결합니다. 복원·메모 저장·팝업 효과는 별도 훅입니다.
- `game-client.ts`는 요청 순서와 실패 복구를 처리하고, `commands.ts`는 행동 이름·필드를 바꿉니다.
- 서버에서는 `policy.ts`가 허용 경로, `request.ts`가 입력, `responses.ts`가 출력, `handle.ts`가 전체 순서를 맡습니다.
- 화면 수정은 `components/기능명/`, 상태·요청·훅 수정은 `app/game/기능명/`에서 합니다. `components` 바로 아래의 예전 단일 파일과 `components/screens`, `hooks`, `lib`는 기존 import를 위한 호환 파일입니다.

소스 파일은 주석을 포함하여 250줄 이내입니다. 이름 있는 함수·클래스는 JSDoc에 역할·입력·반환값을 적습니다. 무명 `map` 콜백이나 이벤트 콜백은 가까운 코드에서 읽도록 두며, 별도 이름을 붙인 도우미는 설명을 작성합니다. `npm test`가 줄 수와 설명 누락을 확인합니다. 자동 생성 잠금 파일과 JSON 검사 자료는 소스 줄 수 대상에서 제외합니다.

## CSS 파일이 여러 개인 이유

`app/layout.tsx`가 `../styles/globals.css`를 한 번 불러옵니다. `globals.css`는 기존 순서대로 나머지 CSS를 연결합니다. 큰 스타일 파일은 기존 규칙 순서를 지키며 `home/`, `investigation/`, `responsive/`의 `part-XX.css`로 나눴습니다. 상위 CSS의 `@import` 순서가 적용 순서입니다. 같은 선택자가 뒤에서 다시 나타날 수 있으므로 파일을 이름순으로 임의 합치거나 규칙을 옮기지 마세요. CSS 회귀 검사는 679개 규칙의 선택자·조건·속성·순서를 확인합니다.
