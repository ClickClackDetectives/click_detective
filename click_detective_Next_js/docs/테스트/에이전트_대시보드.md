# 에이전트 대시보드

Next.js의 `/agent-dashboard`에서 전처리·생성·검증 결과를 확인합니다. FastAPI 연결이 끊겼거나 읽을 진단 기록이 없으면 화면 상단에 **예시 데이터**가 표시됩니다. **연결 및 기록 다시 확인** 버튼으로 최신 상태를 불러옵니다.

## 실측 데이터 연결

1. FastAPI에서 진단 기록을 활성화하고 실제 모델 모드로 심문을 실행합니다.
2. Next.js의 `.env.local`에서 `CLICK_DETECTIVE_API_URL`을 FastAPI 주소로 설정합니다.
3. `CLICK_DASHBOARD_TRACE_PATH`를 FastAPI 진단 JSONL 파일의 절대 경로로 설정하고 Next.js를 재시작합니다. FastAPI의 기본 경로는 `.data/dialogue-traces.jsonl`입니다. 서버가 서로 다른 컨테이너에 있다면 동일한 로그 파일을 Next.js에서 읽을 수 있게 마운트합니다.

경로 설정이 실측 표시를 활성화합니다. 페이지에 접근할 수 있는 사용자는 표시된 진단 수치를 볼 수 있으므로 실측 표시를 켠 환경의 접근 범위를 운영 환경에 맞게 설정하세요.

## 지표 읽기

- 최근 로그 최대 512 KiB에서 완료 기록을 최대 200건 읽습니다. 실행 모드별로 구분합니다.
- 전체 시간은 그래프에서 기록한 처리 시간입니다. 브라우저 왕복 시간과 DB 저장 시간은 별도로 측정합니다.
- 단계별 시간은 기록된 호출 시간을 합산한 요청별 중앙값입니다. 전처리 시간처럼 원본 로그에 없는 수치는 미기록으로 표시합니다.
- 전처리는 승인·선택·필수 사실 수를 표시합니다. 필수 사실 보존율을 계산하려면 실제 전달 여부 기록이 추가로 필요합니다.
- 원문을 보존하지 않는 진단 로그를 사용합니다. 질문·후보 대사·최종 답변은 가상 예시에서 확인할 수 있습니다.
- 버전 표는 파이프라인·모델 이름으로 묶은 관측값입니다. 개선 효과를 판단하려면 같은 질문과 수사 상태로 통제한 별도 실험이 필요합니다.

## 설정과 버전 비교

전처리 탭에서는 RAG 켬·끔, 임베딩·청킹 구성, RAG 버전을 비교합니다. 막대는 처리 시간과 선택 사실 수의 중앙값입니다. 선택 사실 수는 검색 정확도의 지표로 해석할 수 없습니다.

생성 탭에서는 모델, 같은 모델의 QLoRA 켬·끔, 생성 버전을 비교합니다. 막대는 기록된 생성 호출 시간 합계의 중앙값과 첫 후보 통과율입니다. 통과율은 검증기의 판정을 기준으로 합니다. 각 막대에 계산에 포함된 표본 수를 표시합니다.

실측은 현재 선택한 모드와 로그에서 확인되는 설정으로 묶습니다. 비교 가능한 그룹이 둘 미만이면 해당 그래프에만 예시 데이터를 표시합니다.

| 비교 | 로그 키 |
| --- | --- |
| RAG 사용 여부 | `settings.rag_enabled` |
| 임베딩·청킹 | `settings.rag_embedding_enabled`, `settings.rag_chunking_enabled` |
| RAG·생성 버전 | `settings.rag_version`, `settings.generation_version`. 없으면 `pipeline_version` |
| 모델 | `settings.local_model_version` |
| QLoRA | `settings.qlora_enabled`. 기존 로그는 정상 검증 통과 응답의 모델 이름과 어댑터 접미사로 확인 |

현재 검색기는 승인된 사실을 관련성 점수로 선택합니다. 임베딩·청킹은 실험 로그에 해당 설정을 명시한 데이터가 있어야 실측을 표시할 수 있습니다. 기존 로그에서는 전처리 시간이 미기록으로 표시될 수 있습니다. 기존 로그에서 통과 응답의 모델 이름으로 QLoRA를 추정한 표본은 시간 비교에 표시하고 통과율 계산에서 제외합니다.

## 관련성 점수와 ROUGE

FastAPI를 재시작한 뒤 새로 실행한 심문부터 검색 시간과 선택 사실의 평균·최고 관련성 점수가 기록됩니다. 현재 검색기는 ID·단어·두 글자 부분 일치를 합산하므로 1을 넘을 수 있습니다. RAG를 끄거나 선택 사실이 없으면 점수는 미기록입니다. 검색 방식마다 척도가 다르면 점수의 크기를 직접 비교하기 어렵습니다.

생성 탭에서는 모델별·QLoRA별·버전별 ROUGE-1·2·L F1과 생성 시간 p95를 볼 수 있습니다. ROUGE-1은 개별 토큰, ROUGE-2는 연속된 두 토큰, ROUGE-L은 순서를 유지하며 겹치는 토큰을 기준 답변과 비교합니다. 같은 기준 답변·토큰화·평가 대상을 나란히 적용해야 비교할 수 있습니다.

실측 ROUGE는 별도 평가에서 계산한 실행별 점수를 JSONL의 `evaluation`에 함께 넣으면 표시됩니다. 키는 `rouge1_f1`, `rouge2_f1`, `rougeL_f1`이며 0~1 범위입니다. 화면에서는 백분율로 환산합니다. 운영 로그에는 대사 원문과 기준 답변을 넣지 않아도 됩니다. 평가 점수가 없는 실측 실행은 미기록으로 표시됩니다.

## 그래프 화면 전환

상단 버튼으로 전체 요약, 모델별 응답 시간, 전처리, 대사 생성, 검증, 심문 상세, 버전 비교를 전환합니다. 전처리와 대사 생성에서는 비교 기준 버튼을 눌러 한 가지 비교만 펼칩니다.

- 전체 요약의 도넛 그래프는 결과별 비율과 건수를 함께 표시합니다.
- 모델별 응답 시간의 꺾은선은 모델별 중앙값과 p95를 비교합니다. 모델과 시간이 함께 기록된 실행만 집계하고 표본 수를 표시합니다.
- 전처리·대사 생성의 가로 막대는 같은 지표 안에서 설정별 수치를 비교합니다. 각 행에 수치와 유효 표본 수를 표시합니다.
