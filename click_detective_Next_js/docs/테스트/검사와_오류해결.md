# 검사와 오류 해결

명령은 `click_detective_Next_js` 폴더에서 실행합니다.

## 기본 검사

```bash
npm test
npm run typecheck
npm run build
```

| 검사 | 확인 내용 |
| --- | --- |
| `code-conventions.test.ts` | 소스당 250줄·이름 있는 함수와 클래스의 파라미터/반환 설명 |
| `game-client-recovery.test.ts` | 동일 UUID 재확인·확정 실패 해제·저장 버전 복구 |
| `server-cleanup.test.ts` | 검사 프로세스의 시그널 종료·이미 종료한 프로세스 정리 |
| `proxy-policy.test.ts` | 허용 메서드·경로·같은 출처·자산 주소 |
| `ui-source.test.ts` | CSS 규칙과 순서, 기존 고정 화면 문구·속성 |
| `typecheck` | TypeScript 타입·참조 경로 |
| `build` | Next.js 배포용 컴파일과 페이지 생성 |

단위 검사는 별도 서버·외부 원본 폴더 없이 실행합니다. Node 버전에 따라 기본 요약이 중첩 사례 수 대신 검사 파일 수를 보여줄 수 있습니다.

## FastAPI 연결 검사

먼저 빌드한 뒤 실행합니다.

```bash
npm run test:integration
```

스크립트가 형제 폴더 `../click_detective_FastAPI`를 찾고 `.click_venv`, `.venv`, `.cd_venv` 순서로 Python을 찾습니다. 없으면 `python3`를 사용합니다. 별도 fixture 백엔드·Next.js와 임시 SQLite를 만들고 검사 종료 후 정리합니다. 사용 중인 개발 서버나 DB는 검사 대상으로 사용하지 않습니다.

```bash
CLICK_TEST_BACKEND_DIR=/다른/백엔드 \
CLICK_TEST_PYTHON=/사용할/가상환경/bin/python \
npm run test:integration
```

기본 포트는 백엔드 18761·프런트엔드 18762입니다. `CLICK_TEST_BACKEND_PORT`, `CLICK_TEST_FRONTEND_PORT`로 바꿀 수 있습니다. 인증·쿠키·영상 Range·권한·중복 요청·버전 충돌·전체 수사·고발·메모·새 수사를 검사합니다. 결과는 `.reports/integration.json`, 서버 로그는 `.reports/integration-server.log`입니다.

## 화면 비교와 실제 조작

```bash
npx playwright install chromium
CLICK_TEST_ORIGINAL_DIR=/비교할/이전/프런트엔드 npm run test:ui
```

이 명령은 전체 연결 검사와 함께 Chromium을 실행합니다. 비교 소스는 `app`, `components`, `hooks`, `lib`와 Next.js 설정을 가진 이전 UI 프로젝트를 사용합니다. 생략 시 형제 `share_project`를 찾습니다. 현재 구조의 사본이라면 `app/game`은 `app`에 포함되어 복사되며, 루트의 `styles`, `shared`, `server`도 복사합니다. 이전 구조의 루트 `features`도 비교용으로 지원합니다. 원본은 수정하지 않고 임시 폴더에서 실행합니다. 비교 서버 포트는 18763이며 `CLICK_TEST_REFERENCE_PORT`로 변경합니다.

18개 데스크톱·검색·모바일 화면을 같은 상태와 글꼴에서 캡처해 픽셀을 비교합니다. 이전 로컬 API·현재 BFF 양쪽 비교 소스에 같은 수사 데이터를 제공합니다. 과거 UI의 연결 안내 문구 3곳만 비교 페이지에서 현재 안내에 맞춥니다. 새 수사·오프닝·자료 팝업·첨부 심문·메모 자동 저장·새로고침 복원을 실제 조작합니다.

결과는 `.reports/ui/comparison.json`과 각 화면 PNG에 저장합니다. 기본 Linux 라이브러리나 한글 글꼴이 없는 환경은 Chromium 실행 의존성을 준비해야 합니다. 별도 라이브러리를 준비했다면 `CLICK_TEST_BROWSER_LIBS`로 경로를 지정할 수 있습니다.

fixture 연결·화면 검사는 실제 GPU·LLM 응답 품질을 확인하지 않습니다. 외부 웹폰트 요청도 차단한 같은 조건에서 비교합니다.

## 오류를 찾는 순서

| 증상 | 확인할 곳 |
| --- | --- |
| 첫 화면 연결 실패·503 | `.env.local`의 주소·키, 변경 후 재시작 |
| 502 `BACKEND_UNREACHABLE` | FastAPI 실행, `/healthz`, 서버 사이 주소 |
| 504 `BACKEND_TIMEOUT` | 백엔드 로그·모델 처리 시간, 타임아웃 설정 |
| 401 또는 수사 없음 | 두 서버 키 일치, 수사 쿠키, 새 수사 시작 |
| 403 `ORIGIN_REJECTED` | 접속한 호스트·포트와 요청 Origin |
| 409 버전 충돌 | 다른 탭의 변경, 상태 재조회 및 동일 요청 재확인 |
| 413 `BODY_TOO_LARGE` | 요청 본문 크기 |
| 심문 오류 | FastAPI 오류 코드·생성 모드·모델 환경 |
| 비교 소스 없음 | `CLICK_TEST_ORIGINAL_DIR` 지정 |
| 포트 사용 중 | 테스트 포트 변경 또는 자신이 실행한 서버 종료 |
