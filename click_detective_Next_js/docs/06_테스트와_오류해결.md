# 테스트와 오류 해결

## 1. 어떤 검사를 먼저 실행하는가

아래 명령은 `click_detective_nextjs` 폴더에서 실행합니다.

```bash
cd ~/reverse/click_detective_nextjs
npm run typecheck
npm test
npm run build
npm run test:integration
npm run test:ui
```

| 명령               | 확인하는 것                                                 | 실제 서버·GPU                 |
| ------------------ | ----------------------------------------------------------- | ----------------------------- |
| `typecheck`        | TypeScript 타입 연결                                        | 서버·GPU 불필요               |
| `test`             | 중계 정책·자산 경로·원본 소스 동일성·실패 후 요청 복구 검사 | 서버·GPU 불필요               |
| `build`            | 배포 가능한 Next.js 출력                                    | 게임 서버·GPU 불필요          |
| `test:integration` | 실제 Next.js → FastAPI HTTP 전체 게임                       | 임시 서버·fixture, GPU 불필요 |
| `test:ui`          | HTTP 검사에 더해 원본 화면·브라우저 동작 비교               | 임시 서버·Chromium·fixture    |

`test:integration`과 `test:ui`는 **빌드 결과를 실행**합니다. 소스를 바꿨다면 먼저 다시 `npm run build`를 실행하세요. 두 검사는 기본 포트가 같으므로 동시에 실행하지 않습니다.

`npm test`에는 원본 파일 비교가 포함되므로 `share_project`가 필요합니다. 일반 앱 실행에 원본 폴더가 필요한 것은 아닙니다.

## 2. 통합 검사의 실행 환경

스크립트는 이웃 `click_detective/.cd_venv/bin/python`을 사용합니다. 임시 API 키·임시 SQLite DB·fixture 모드로 FastAPI를 켜고 Next.js도 별도로 실행합니다. 기존 `.env`와 운영 DB를 수정하지 않습니다.

| 설정                        | 기본값                  |
| --------------------------- | ----------------------- |
| `CLICK_TEST_BACKEND_DIR`    | 이웃 `click_detective`  |
| `CLICK_TEST_BACKEND_PORT`   | 18761                   |
| `CLICK_TEST_FRONTEND_PORT`  | 18762                   |
| `CLICK_TEST_ORIGINAL_DIR`   | 이웃 `share_project`    |
| `CLICK_TEST_REFERENCE_PORT` | 18763, UI 검사에서 사용 |

프로젝트 위치가 다르면 필요한 경로를 절대 경로로 지정합니다. 예를 들어 포트를 피해서 HTTP 검사만 실행할 수 있습니다.

```bash
CLICK_TEST_BACKEND_PORT=18861 \
CLICK_TEST_FRONTEND_PORT=18862 \
npm run test:integration
```

스크립트는 자신이 띄운 프로세스를 종료하고 임시 DB 폴더를 정리합니다. 강제 종료나 포트 충돌 시에는 로그를 확인하세요.

## 3. 검사 내용과 파일

HTTP 검사는 카탈로그·사건·자산·Range·쿠키·미획득 자료 거절·중복 UUID·오래된 revision·자료 열람·심문·추론·쟁점·2차 조사·메모·고발·종결 후 거절·새 수사를 확인합니다.

자동 진행 입력은 **백엔드 내부 실제 사건 데이터**에서 읽습니다. 테스트 스크립트만 비공개 규칙을 읽어 전체 경로를 확인하며, 운영 페이지가 이 스크립트를 가져와 정답을 읽는 구조는 아닙니다.

| 산출물                            | 내용                                    |
| --------------------------------- | --------------------------------------- |
| `.reports/integration.json`       | HTTP 검사 모드·성공 여부·입력·출력·상태 |
| `.reports/integration-server.log` | 실행한 서버 로그                        |
| `.reports/ui/comparison.json`     | 화면별 픽셀 비교·브라우저 동작 결과     |
| `.reports/ui/*-actual.png`        | 새 프로젝트 화면                        |
| `.reports/ui/*-original.png`      | 격리한 원본 화면                        |

JSON의 `passed`가 true인지 먼저 확인한 뒤, HTTP `records`의 `expectedStatus`와 `status`를 비교합니다. 일부 400·403·404·409·422는 의도한 거절 검사입니다. 상태가 200이 아니라는 이유만으로 실패로 판단하지 않습니다.

이미지·영상 응답은 전체 바이너리 대신 요약 정보를 기록합니다. `bytes` 값은 스크립트의 텍스트 변환 후 바이트 계산값이므로 원본 파일 크기 검사로 해석하지 않습니다. 서버 로그와 보고서는 재실행 시 갱신될 수 있으며, UI 보고서는 해당 UI 검사가 실행된 시점과 함께 읽어야 합니다.

## 4. 브라우저 검사 준비

```bash
cd ~/reverse/click_detective_nextjs
npx playwright install chromium
```

Linux에서 공유 라이브러리가 부족하면 관리 권한으로 Playwright 시스템 의존성 설치가 필요할 수 있습니다.

```bash
npx playwright install-deps chromium
```

이 명령은 시스템 패키지 설치를 시도하므로 해당 PC의 관리 권한 정책에 따라 실행하세요. 현재 작업 환경에는 시스템을 수정하지 않고 준비한 `.browser-libs`가 있으며, 스크립트는 해당 라이브러리 경로와 폰트 설정이 있으면 사용합니다. 이 폴더는 Git 제외 대상이므로 다른 PC에 자동으로 생기는 것은 아닙니다.

원본 비교 서버는 원본의 `node_modules`와 `public`을 참조합니다. 새 환경에서는 원본 의존성도 준비되어 있어야 합니다. 검사 방식은 [UI 비교 문서](09_원본_UI_UX_유지와_비교검사.md)에 설명되어 있습니다.

## 5. 상태·코드별 오류 확인

| 표시 또는 코드                | 의미                                     | 먼저 확인할 것                            |
| ----------------------------- | ---------------------------------------- | ----------------------------------------- |
| 연결 전 화면의 오류           | catalog를 받지 못함                      | FastAPI 실행 완료, 주소, API 키           |
| `SERVER_CONFIG` / 503         | Next.js 서버 설정 누락·잘못된 URL        | `.env.local`, 재시작, 외부 환경변수       |
| `BACKEND_UNREACHABLE` / 502   | FastAPI 연결 실패·중계 통신 실패         | 포트·호스트·모델 시작 로그                |
| `BACKEND_TIMEOUT` / 504       | 중계 응답 대기 초과                      | 모델 처리 시간·백엔드 로그·동일 UUID 복구 |
| `BACKEND_401`                 | 서비스 키 불일치                         | 두 환경변수 파일의 키 일치                |
| `NO_GAME` / 401               | 수사 쿠키 없음                           | 수사 시작, 쿠키 설정                      |
| `ORIGIN_REJECTED` / 403       | 출처 불일치 또는 Origin 없음             | 접속 주소·프록시 Host·프로토콜            |
| `UNKNOWN_ROUTE` / 404         | 허용하지 않은 BFF 경로                   | API 표와 메서드·경로                      |
| `BACKEND_404`                 | 사건·자료·수사 접근 대상 없음 등         | 대상 ID·획득 단계·토큰                    |
| `BACKEND_409`                 | 버전·UUID·종결 상태 등의 충돌            | 화면 최신 상태와 원문 메시지              |
| `operation_in_progress` / 409 | 동일 요청 처리 중                        | 기존 요청 결과를 먼저 재확인              |
| `BACKEND_422`                 | 입력 형식·획득 조건·조합·단계 등 거절    | 필수 입력·자료·행동 조건                  |
| `INVALID_JSON` / 400          | JSON 객체 형식 아님                      | 본문 배열·문법·Content-Type               |
| `BODY_TOO_LARGE` / 413        | 본문 크기 초과                           | 입력 크기                                 |
| `INVALID_RESPONSE` / 502      | 생성 응답에 필수 필드 누락               | 프런트·백엔드 계약 버전                   |
| 생성 관련 별도 코드 / 502·504 | strict 모델 오류 또는 복구 설정 비활성화 | 백엔드 진단 로그와 생성 오류 코드         |

BFF는 상세 Pydantic 오류 배열을 그대로 표시하지 않고 일반 입력 안내로 바꿀 수 있습니다. 심문 실패를 브라우저에서 임의 정답으로 대체하지 않습니다. 백엔드 오류는 [백엔드 문제 해결 안내](../../click_detective/docs/08_테스트_진단_문제해결.md)도 참고하세요.

## 6. 영상·이미지·폰트가 이상할 때

- 저택 배경: `/manor.jpg` 응답을 확인합니다.
- 노트 종이 배경: `/assets/notebook-paper.png`를 확인합니다.
- 오프닝: `/assets/intro/thirteenth-bell-opening-v3-quiet.mp4`와 Range 응답을 확인합니다.
- 인물: 카탈로그 portrait가 `/api/detective/assets/...`로 바뀌었는지 확인합니다.
- 증거 이미지: 획득 후 보호된 `evidence-assets` 경로를 사용하는지 확인합니다.

노트가 평평한 단색으로 보이면 원본 CSS가 바뀐 것뿐 아니라 배경 이미지 404도 원인일 수 있습니다. `/assets/...`의 백엔드 대응에는 `assets/assets`가 들어갈 수 있습니다.

영상 전체 GET의 200과 부분 요청의 206은 모두 정상일 수 있습니다. 브라우저 자동 재생 차단과 서버 영상 404는 다른 문제입니다. 폰트 서버 접근 실패·한글 폰트 미설치도 원본 CSS 변경과 구분해서 확인합니다.

## 7. 메모와 새로고침 확인

메모 입력 직후에는 아직 저장 전일 수 있습니다. ‘저장됨’ 또는 실제 PUT 응답을 확인한 뒤 새로고침하세요. UI 자동화에서도 입력 이전의 ‘저장됨’을 잘못 읽지 않도록 **해당 저장 요청의 성공 응답**을 기다립니다.

409가 반복되면 여러 탭의 동시 변경을 확인합니다. 중계 통신 실패·중계 시간 초과처럼 결과가 불확실할 때만 이전 UUID를 먼저 복구합니다. 서버가 생성·검증 실패를 확정한 502·504는 다음 질문을 막지 않습니다. 오류를 피하려고 곧바로 같은 질문을 새로운 별도 요청으로 반복하는 방식은 피합니다.

## 8. 이미 확인된 결과를 읽는 방법

현재 저장된 기존 보고서는 fixture HTTP 149건 성공, 화면 18개 일치, 브라우저 동작 묶음 5개 성공입니다. 백엔드 pytest는 별도 실행에서 15개 통과했습니다. 문서 재작성 시에는 이 보고서를 읽어 설명했으며 전체 실행을 새로 반복하지 않았습니다.

테스트 코드가 늘어나면 건수는 바뀔 수 있습니다. 실제 실행의 출력과 해당 보고서의 생성 시각을 우선합니다. 실제 Qwen 생성 품질·양자화·어댑터 적용 확인은 local 모드 백엔드에서 별도로 수행해야 합니다.

## 기본 플레이와 LLM 품질 검사

기본 true에서는 모델 실패에도 승인 원문 fallback이므로 HTTP 200과 대화가 보이는 것이 정상입니다. stop 생성 성공과 구분하세요. 실서버 LLM 도구는 fallback을 품질 성공으로 세지 않습니다. 현재 보관된 백엔드 회귀 보고서는 31개 통과이며 그중 플레이 복구를 별도 검사합니다. 문서 갱신을 위해 실제 GPU를 재실행한 것은 아닙니다.
