# 인증과 수사 상태 관리

화면 상태·공식 저장 상태·서버 인증 정보를 구분하고, 한 행동이 실패했을 때 어떻게 복구하는지 설명합니다.

## 실행 장소별 책임

| 위치 | 하는 일 | 사용하는 정보 |
| --- | --- | --- |
| 브라우저 | 화면·초안·검색·메뉴·팝업 | 공개 카탈로그와 반환된 수사 상태 |
| Next.js 서버 | 허용 경로 중계·인증 추가·쿠키 설정 | 서버 환경변수의 서비스 키, 수사 쿠키 |
| FastAPI | 권한 검사·규칙 판정·에이전트·공식 저장 | 사건 데이터, 수사 저장소, 계정 세션 |

브라우저는 같은 출처의 `/api/detective/...`와 `/api/auth/...`를 호출합니다. Next.js가 `Authorization: Bearer ...`와 수사 요청에 필요한 계정 인증 헤더를 쿠키에서 읽어 FastAPI에 붙입니다.

## 서버 중계 순서

`app/api/detective/[...segments]/route.ts`는 GET·POST·PUT을 `server/proxy/handle.ts`의 `handle`로 연결합니다.

1. GET 외 요청의 Origin이 같은 사이트인지 확인합니다.
2. `resolveTarget`이 메서드와 경로를 허용 목록으로 검사합니다.
3. 수사 ID·토큰 쿠키를 읽고 필요한 경우 존재 여부를 확인합니다.
4. 백엔드 URL·키를 확인하고 `addSearchParams`로 허용한 검색 조건만 붙입니다.
5. `readBody`가 JSON 객체 형식과 100000바이트 제한을 검사합니다.
6. 서비스 키·수사 토큰·선택적 Range를 붙여 FastAPI에 전달합니다.
7. 생성 응답은 `gameCreated`, 오류는 `upstreamError`, 나머지는 `streamResponse`가 처리합니다.

임의의 서버 주소를 요청할 수 있는 프록시는 아닙니다. `policy.ts`의 허용 경로로만 전달됩니다.

## 쿠키와 저장 위치

메인에서 새 수사를 만들면 FastAPI가 로그인 계정을 소유자로 저장합니다. 메인에 진입하면 현재 계정의 최근 갱신 수사를 불러오고, 이후 요청은 열린 수사의 UUID로 범위를 고정합니다. 계정에 저장된 수사가 없으면 새 수사를 시작할 수 있습니다.

공식 수사 기록은 FastAPI의 MongoDB에 있습니다. React 상태에는 받은 기록과 입력 중인 초안이 있습니다. localStorage에는 수사별 오프닝 열람 여부만 저장합니다. 쿠키를 지우면 브라우저가 기존 수사에 접근할 정보가 사라집니다.

## 요청 큐·저장 버전·실패 복구

```ts
export function requestGame(action: string, body?: unknown): Promise<GameState | null>
```

`game-client.ts`의 `queue`는 요청을 앞선 작업 뒤에 연결합니다. `latest`는 마지막 확인 상태, `pending`은 결과가 불확실한 변경 요청입니다.

| 값 | 의미 | 예 |
| --- | --- | --- |
| `request_id` | 한 행동의 고유 UUID | 같은 요청 재확인 시 같은 값 |
| `expected_revision` | 현재 알고 있는 저장 버전 | 서버 버전과 다르면 409 |
| `fingerprint` | 행동·입력을 직렬화한 값 | 이전 행동의 재시도인지 비교 |

통신 단절·시간 초과·처리 중 응답은 저장 성공 여부를 확정할 수 없습니다. 다음 요청 전에 `pending`을 같은 UUID로 다시 확인합니다. 같은 행동이면 복구 결과를 반환하고, 다른 행동이면 복구 후 새 요청을 만듭니다. 생성·검증 오류처럼 서버가 실패를 확정한 응답은 대기 요청에서 제거합니다. 확정된 409 충돌은 상태 조회로 최신 버전을 복원합니다.

`accept`는 같은 수사의 오래된 revision으로 최신 상태를 되돌리지 않습니다. 수사 ID가 바뀌면 새 수사로 받아들입니다.

## 계정과 수사 선택

사건 시작, 이어하기와 수사 진행에는 로그인이 필요합니다. 로그인하지 않은 상태에서 시작이나 기록 열기를 누르면 **로그인을 하세요** 안내가 열립니다. Next.js 중계는 공개 사건 목록과 공개 자산 외의 수사 요청에서 활성 세션을 확인합니다.

- 메인 화면 상단의 **로그인** 버튼에서 `/login`으로 이동합니다. **회원가입**은 로그인 화면에서 선택합니다. 어느 화면에서 로그인해도 성공하면 메인 화면(`/`)으로 이동합니다. 로그인·회원가입 페이지를 열면 접근 토큰을 확인하고 필요하면 갱신 쿠키로 세션을 복원합니다. 활성 세션이 확인되면 메인 화면으로 이동합니다. 세션 확인과 인증 요청을 처리하는 동안에는 빈 화면을 표시하고, 제출에 실패하면 입력 폼과 오류를 다시 표시합니다. 가입 비밀번호는 8~16자이며 영문 대소문자 중 하나, 숫자와 `!`, `@`, `#` 같은 ASCII 특수문자를 각각 포함해야 합니다. 사건 자료를 불러오는 중이거나 계정 확인에 실패해도 로그인으로 이동할 수 있습니다. 로그인하면 같은 자리에 계정 이메일과 **로그아웃**이 표시됩니다. 계정에 연결한 수사는 `/game?investigation=<수사 UUID>`에서 엽니다.
- 이전 브라우저 수사 쿠키는 계정 기록 복원에 사용하지 않습니다. 기존 연결 API에서 명시적으로 이전 수사를 연결할 때는 FastAPI가 계정과 해당 익명 토큰을 모두 검사합니다.
- 계정 중계는 `cd_access_token`을 `Path=/`, `cd_refresh_token`을 `Path=/api/auth`에 저장합니다. 두 쿠키는 HttpOnly·SameSite=Lax이며 HTTPS에서 Secure를 사용합니다. 토큰 쌍은 공개 응답에 포함되지 않습니다.
- 계정 수사는 FastAPI의 PostgreSQL 세션과 MongoDB 소유권을 확인합니다. URL에 지정한 수사 ID로 접근하더라도 FastAPI가 각 요청의 소유자를 확인합니다.
- 계정 수사 접근 쿠키가 없거나 만료되면 웹 잠금 지원 환경에서 탭 간 갱신을 직렬화합니다. 계정이 같으면 직전 요청의 본문, UUID와 revision을 유지해 한 번 다시 보냅니다. 화면의 계정 또는 수사가 바뀌면 이전 범위의 대기 요청과 응답을 적용하지 않습니다.
- 로그아웃은 FastAPI가 갱신 쿠키나 접근 쿠키로 세션 폐기를 확인한 뒤에만 쿠키를 지웁니다. 실패하면 화면에 오류를 표시합니다.
