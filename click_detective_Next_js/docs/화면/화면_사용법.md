# 화면 사용법

현재 `components/`의 메뉴 이름·버튼·팝업을 기준으로 설명합니다. 화면별 함수 선언은 [화면 코드 목록](../코드참조/README.md)에 있습니다. 화면은 서버가 돌려준 상태를 표시하며, 조건을 충족하지 못한 행동은 FastAPI가 거절할 수 있습니다.

## 1. 홈과 사건 기록실

홈에는 원본의 사건 소개·시작 버튼·수사 방식 안내가 나타납니다. 처음에는 ‘첫 번째 사건 시작하기’, 진행 중인 기록이 있으면 ‘수사 이어하기’를 사용합니다.

상단 ‘사건 기록’ 또는 ‘사건 목록 보기’를 누르면 사건 카드 화면으로 이동합니다. 플레이 가능한 사건은 현재 열세 번째 종 한 개이며, 나머지 카드는 준비 중 안내 팝업을 보여줍니다. 카드가 존재한다고 모든 사건을 시작할 수 있는 것은 아닙니다.

‘내 수사 기록’은 현재 열어 둔 수사의 브리핑 또는 종결 결과를 엽니다. 기록이 없으면 첫 수사를 안내하는 팝업을 표시합니다. 로그인하지 않고 사건을 시작하거나 기록을 열면 **로그인을 하세요** 팝업이 표시됩니다. 로그인하면 상단의 로그인 버튼 자리에 계정 이메일과 **로그아웃**이 표시됩니다.

## 2. 브리핑과 오프닝

사건을 시작하면 브리핑으로 이동합니다. 새 수사에서 브리핑을 처음 열면 원본 오프닝이 자동 표시됩니다. 닫기·Escape·음량 조절·다시 보기·재생 제한 안내 등 기존 동작을 유지합니다.

오프닝 표시 여부는 `detective-opening-v3:{gameId}`라는 localStorage 키로 기억합니다. 이는 **영상을 이미 표시했는지**를 기억하는 용도입니다. 끝까지 감상했다는 서버 기록이나 게임 진행률은 아닙니다.

브라우저가 자동 재생을 막으면 화면의 재생 안내를 사용하세요. 같은 수사의 오프닝을 다시 보고 싶으면 재시청 버튼을 사용합니다. 영상 오류가 있으면 [자산 경로와 Range 확인](../테스트/검사와_오류해결.md)을 참고하세요.

## 3. 증거 보관실

1. 왼쪽 메뉴에서 ‘증거 보관실’을 엽니다.
2. 전체 또는 장소 버튼으로 범위를 고릅니다.
3. 필요하면 ‘증거 검색’에 번호·제목·장소·요약 관련 검색어를 입력합니다.
4. 자료 카드를 누르면 열람이 확정되고 본문 팝업이 열립니다.
5. 이미지가 있는 자료는 원본과 같은 위치에 참고 일러스트가 표시됩니다.

장소별 자료·검색 결과·열람 수는 서버가 제공합니다. 아직 다음 단계의 자료는 해당 단계가 열리기 전 목록에서 제외됩니다. 검색은 원본과 같이 앞뒤 공백을 제거한 소문자 비교를 사용하며, 의미 기반 RAG 검색과는 다른 기능입니다.

팝업의 ‘심문에 증거 제시’를 누르면 심문실로 이동하고 해당 자료가 선택됩니다. 팝업 닫기·바깥 영역 클릭·Escape·Tab 포커스 이동도 유지합니다. 종결 후 미열람 자료는 읽지 못할 수 있습니다.

## 4. 증언 기록

‘증언 기록’은 원본 자료에 포함된 집사 문서, 인물의 최초 진술, 실제 심문 대화, 서버가 기록한 획득 진술을 구분해서 표시합니다.

| 분류                  | 의미                                 |
| --------------------- | ------------------------------------ |
| 전체                  | 최초 진술·집사 문서·획득 진술·대화   |
| 확보한 동선 진술      | 동선 주제로 실제 확보한 진술         |
| 다른 인물에 대한 진술 | 다른 인물에 관한 주제로 확보한 진술  |
| 심문에서 인정         | 심문에서 인정한 내용으로 분류된 진술 |
| 전체 심문 대화        | 질문과 그에 대응하는 답변 쌍         |

증언자 버튼과 검색창으로 범위를 좁힐 수 있습니다. 서버는 질문·답변이 짝을 유지하도록 검색 결과를 구성합니다. 진술의 ‘심문 원문’, ‘타임라인’, ‘제시 자료’, ‘대본 출처’로 관련 기록을 다시 확인할 수 있습니다.

이전 주장과 이후 인정이 다른 경우에는 원문을 삭제하지 않고 수정 진술임을 표시합니다. 대화 말풍선이 생성되었다고 모든 문장이 별도의 공식 증언 항목으로 등록되는 것은 아닙니다.

## 5. 용의자 심문

인물 선택 → 주제 선택 또는 자유 질문 작성 → 필요하면 자료 첨부 → ‘질문하기’ 순서입니다.

- 주제 버튼은 서버에서 공개한 질문 문구를 입력창에 넣습니다.
- 질문을 직접 수정하면 이전 주제 ID가 해제되어 자유 질문으로 전달됩니다.
- 제시 자료는 실제 획득한 원본 자료 또는 생성된 추론 중에서 선택합니다.
- 입력은 1,000자까지이며 남은 질문 횟수가 표시됩니다.
- 성공하면 질문·주제·첨부 초안이 비워지고 답변이 말풍선으로 표시됩니다.

수사 전체 질문 제한은 현재 서버 설정상 25회이며 자료를 첨부한 심문도 포함합니다. 백엔드는 유효한 심문을 접수할 때 1회 차감합니다. 모델 오류가 표시된 뒤에도 이미 접수한 심문은 사용 횟수에 포함됩니다.

‘FastAPI 연결’ 안내는 실제 중계 연결 구조를 뜻합니다. 현재 백엔드가 fixture 모드인지 local 모델 모드인지는 별도로 확인해야 합니다. 화면이 임의로 대사를 만들지는 않습니다. 백엔드는 모델 생성·검증이 실패하면 승인된 원문만 사용해 대사를 복구합니다(fallback). 승인 정보가 없는 질문은 중립 답변(fixed)을 반환합니다. 쟁점이 없는 질문도 정상 답변을 받습니다.

## 6. 발견한 쟁점

실제 심문에서 발견된 쟁점, 관련 인물, 제시 자료, 해당 답변을 확인합니다. 자료를 읽는 행동과 쟁점을 발견하는 행동은 다릅니다. 필요한 자료를 제시하고 관련 질문을 해야 할 수 있습니다.

쟁점의 링크를 누르면 관련 자료를 다시 열 수 있습니다. 미발견 정답 목록을 사전에 모두 보여주는 화면은 아닙니다.

## 7. 추론 증거

‘자료 연결’에서 증거·증언·추론 분류를 오가며 실제 획득한 출처 2~4개를 선택합니다. 검색은 번호·제목·인물 등의 표시 정보를 대상으로 합니다.

선택한 자료는 분류를 바꿔도 유지됩니다. 선택한 칩을 누르면 해제됩니다. ‘선택한 자료 연결’을 누르면 서버가 출처 권한과 조합을 검사합니다. 적합한 조합이면 추론 문서를 만들고, 이미 확보한 연결이면 중복 문서를 만들지 않습니다. 인정되지 않는 조합은 오류를 표시합니다.

생성된 문서에서는 도출한 결론, 직접 연결한 자료, 펼쳐 본 원본 근거, 기본/연쇄 추론 분류를 확인합니다. 추론 문서도 심문에 제시할 수 있습니다. 단순히 출처를 아무렇게나 선택하면 LLM이 정답 추론을 자유 생성하는 기능은 아닙니다.

## 8. 2차 조사와 타임라인

현재 2차 조사 조건은 추론 증거 2개와 심문 쟁점 2개 이상입니다. 증거실의 ‘2차 조사 시작’은 서버가 계산한 충족 여부에 따라 활성화됩니다. 클릭 시 FastAPI가 다시 검사하고 추가 자료를 공개합니다.

‘사건 타임라인’은 공개 일정과 실제 획득한 진술·자료·추론을 시간대별로 배치합니다. 예정 시각·목격·본인 진술·추론을 같은 확정 사실로 취급하지 않도록 분류가 표시됩니다. 증언이나 자료 링크로 근거를 확인할 수 있습니다.

## 9. 수사 노트

입력이 **700ms 멈추면 자동 저장**을 시도합니다. 진행 중인 일반 행동이 있으면 해당 처리가 끝난 뒤 저장을 시도합니다. 자동 저장 요청도 공통 큐를 통해 순서대로 전송됩니다.

‘저장 대기 중’ → ‘저장 중…’ → ‘저장됨’을 확인하세요. 실패하면 ‘지금 저장’으로 다시 시도할 수 있습니다. ‘지금 저장’은 강제로 다른 행동을 동시에 실행하는 버튼이 아니라 같은 저장 요청 흐름을 사용합니다.

메뉴를 옮겨도 부모 컨트롤러가 초안을 보관합니다. 저장되지 않은 메모가 있으면 페이지 이탈 경고를 유지합니다. 강제 종료나 쿠키 삭제로 미저장 초안을 복구하는 기능은 없습니다. 종결된 수사는 노트를 읽기 전용으로 표시합니다.

## 10. 최종 고발과 결과

수사를 시작한 뒤 조사 단계·진행률·쟁점 수와 관계없이 범인·동기·수단을 선택해 고발할 수 있습니다. 제출할 추론 증거는 선택 사항이며, 0개도 허용합니다. 증거 목록에는 특정 추론을 ‘필수’로 표시하지 않습니다. 부족한 근거는 제출을 막는 대신 결과의 입증 평가에 반영합니다. 이미 종결된 수사는 결과 화면으로 안내합니다.

제출 버튼 → ‘고발을 확정하시겠습니까?’ 팝업 → ‘고발 확정’ 순서로 진행합니다. 서버는 선택값과 실제 근거를 검증하고 수사를 종결합니다. 결과 화면에서 입증 완료/실패 항목, 근거 평가, 발견/미발견 항목을 확인합니다.

‘다시 수사하기’는 확인 팝업 후 새 수사를 만듭니다. 새 수사도 현재 로그인 계정에 저장합니다.

## 11. 모바일과 오류 표시

작은 화면에서는 기존 반응형 CSS와 ‘수사 메뉴 열기’ 버튼을 사용합니다. 메뉴 선택 후 모바일 메뉴를 닫고 해당 화면으로 이동합니다.

일반 행동 오류는 원본 오류 토스트로 표시합니다. 검색 API 오류는 해당 자료 화면에서도 표시할 수 있습니다. 실패 메시지를 닫는 것은 서버에서 실패 원인이 해결됐다는 뜻이 아닙니다.

## 복구된 답변의 기록

모델 실패 후 승인 원문으로 받은 fallback도 실제 답변이므로 질문 1회·대화로 저장합니다. 쟁점 없는 질문에는 새 쟁점이 생기지 않고, 승인 조건을 충족한 인정 답변만 해당 쟁점으로 기록합니다. 질문 한도·종결·인증·버전 조건은 유지합니다. [상세 정책](../../../click_detective_FastAPI/docs/에이전트/응답과_복구_정책.md)

## 계정별 수사 이어하기

1. 로그인하고 메인에서 사건을 시작합니다. 진행도와 메모는 로그인 계정에 저장됩니다.
2. 같은 계정으로 다시 로그인하면 메인 화면에서 최근 수사를 이어갈 수 있습니다. 다른 브라우저에서도 같은 계정의 저장 기록을 불러옵니다.
