# 파일별 코드 설명

이 문서는 코드를 수정할 때 어느 파일부터 읽을지 안내합니다. 원본 디자인 파일과 새 연결 코드를 구분해서 읽으면 구조를 이해하기 쉽습니다.

## 1. 진입점과 원본 스타일

| 파일                           | 역할                           | 수정할 때 주의할 점                                      |
| ------------------------------ | ------------------------------ | -------------------------------------------------------- |
| `app/page.tsx`                 | 첫 페이지에서 로더 실행        | 여기에 게임 엔진을 넣지 않음                             |
| `app/layout.tsx`               | 한국어 HTML·메타데이터·CSS     | 원본 바이트 비교 대상                                    |

## 2. 최초 카탈로그 로더

`components/original-app-loader.tsx`의 `OriginalAppLoader`는 서버 자료가 준비되기 전에 원본 컴포넌트가 빈 배열을 읽지 않도록 합니다.

`api('catalog')` → 인물 portrait의 중계 주소 변환 → `installCatalog` → `installLibrary` → `installStage` → `installAccusation` → `CaseApp` 표시 순서입니다. 실패하면 연결 메시지와 ‘다시 연결’ 버튼을 표시합니다. `alive` 플래그는 이미 정리된 effect의 결과를 화면에 적용하지 않도록 합니다.

## 5. useCaseGame 컨트롤러

`hooks/use-case-game.ts`는 원본 사용 흐름을 유지하는 중심 훅입니다.

| 주요 값·함수                         | 역할                                        |
| ------------------------------------ | ------------------------------------------- |
| `state`                              | 공식 수사 상태                              |
| `view`, `modal`, `mobile`            | 화면·팝업·모바일 메뉴                       |
| `question`, `topicId`, `attachment`  | 심문 입력 초안                              |
| `notes`, `noteStatus`, `latestNotes` | 메모 초안·저장 표시·최신 입력 참조          |
| `updateGame`                         | 잠금·busy·오류·성공 상태 적용               |
| `navigateTo`                         | 메뉴 이동·모바일 메뉴 닫기·문서 닫기·스크롤 |
| `startInvestigation`                 | 이어하기 또는 새 수사와 입력 초기화         |
| `openEvidence`                       | 필요한 열람 확정 후 본문 API 조회           |
| `submitQuestion`                     | 질문 제출 후 성공 시 입력 초기화            |

effect는 수사 복원, 말풍선 스크롤, 팝업 포커스·Escape·Tab, 700ms 메모 자동 저장, 페이지 이탈 경고를 담당합니다. `stateRef`와 `latestNotes`는 비동기 처리 시 최신 값을 확인하기 위한 참조입니다.

자동 저장이 성공해도 그 뒤 사용자가 더 입력했다면 이전 스냅샷으로 최신 초안을 덮어쓰지 않습니다. 일반 행동 실패 시 `currentGame()`을 읽어 클라이언트가 확인한 최신 공식 상태를 반영합니다.

## 6. useScreenView 조회 훅

`hooks/use-screen-view.ts`는 `screen`, `state`, 검색 조건, 초기 표시값을 받습니다. screen·검색 조건·게임 ID·revision이 바뀌면 `/views/{screen}`을 다시 조회합니다.

`EvidenceView`, `TestimonyView`, `InferenceView` 타입은 화면 조회 응답을 설명합니다. `alive`로 이전 조회 응답을 무시하며 서버 검색 결과와 오류를 컴포넌트에 돌려줍니다. 현재 구현에는 검색 입력 debounce를 별도로 두지 않습니다.

## 7. game-client.ts 어댑터

`lib/game-client.ts`는 원본 행동 인터페이스와 FastAPI 사이를 연결합니다.

| 구성              | 책임                                   |
| ----------------- | -------------------------------------- |
| `command`         | 행동·필드 이름 변환                    |
| `latest`          | 현재 탭이 확인한 최신 공식 상태        |
| `accept`          | 낮은 revision으로 상태를 되돌리지 않음 |
| `queue`           | 행동을 순서대로 실행하는 Promise 체인  |
| `pending`         | 결과를 확정하지 못한 요청 본문·UUID    |
| `send`            | 전송·오류 분류·보류·409 상태 갱신      |
| `requestGame`     | 복원·이어하기·생성·변경의 공통 호출    |
| `currentGame`     | 오류 후 확인 가능한 최신 상태 반환     |
| `requestDocument` | 보호된 본문을 원본 팝업 타입으로 변환  |

`requestDocument`는 진술의 실제 답변·화자·출처를 조합해 팝업을 표시합니다. 서버가 확정한 정보를 표시용 문자열로 조합하는 과정이며, 새 사실이나 정답을 생성하지 않습니다.

## 9. 서버 Route Handler

`app/api/detective/[...segments]/route.ts`는 `GET`, `POST`, `PUT`을 처리합니다. Next.js 16의 params Promise를 await한 뒤 경로 정책을 적용합니다.

출처 검사 → 수사 쿠키 → 허용 경로 → 환경변수 → 본문 형식·크기 → FastAPI fetch → 오류 또는 안전한 응답 순서입니다. 생성은 토큰을 JSON에서 빼고 쿠키로 저장합니다. 자산은 필요한 콘텐츠 헤더만 전달해 스트리밍합니다.

`app/assets/[...asset]/route.ts`와 `app/manor.jpg/route.ts`는 원본 URL을 같은 중계 함수로 연결합니다. 이 파일에서 별도 API 키 처리나 게임 엔진을 만들지 않습니다.

## 11. 수정 목적에 따른 시작 위치

화면 구성은 해당 screen에서, API 필드 이름은 `game-client.ts`에서, 인증·중계 오류는 Route Handler에서, 검색 응답은 백엔드 `screen_views.py`에서 확인합니다. 게임 정답·획득 조건·점수는 Next.js에 새로 구현하지 않고 백엔드를 수정합니다.

원본 UI 변경이 의도된 작업이라면 비교 기준과 테스트도 함께 검토해야 합니다. 원본 바이트 비교가 실패한다고 무조건 테스트만 삭제하지 않습니다.

## 백엔드 복구와 화면 책임

GameService.reply가 승인 원문 fallback을 제공하므로 화면이 오류 때 정답 문장을 만들어내지 않습니다. game-client는 정상 fallback state를 받아 저장 버전을 갱신하고 기존 말풍선으로 표시합니다. 완료 응답과 불확실한 통신 실패를 구분해 재전송합니다.
