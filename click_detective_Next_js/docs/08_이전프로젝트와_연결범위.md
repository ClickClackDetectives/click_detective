# 원본 프로젝트와 연결 범위

## 1. 세 프로젝트의 관계

| 프로젝트                 | 현재 역할                                               |
| ------------------------ | ------------------------------------------------------- |
| `share_project`          | UI·UX·CSS·원본 기능의 기준, 비교용 원본                 |
| `click_detective`        | 사건 데이터·규칙·LLM·검증·저장 담당 FastAPI             |
| `click_detective_nextjs` | 원본 화면을 유지하며 FastAPI에 연결하는 실제 프런트엔드 |

원본 자체에 FastAPI 코드를 덧붙이는 작업이 아닙니다. 새 프로젝트가 원본 화면을 사용하며 원본은 수정하지 않습니다. 예전의 별도 디자인 컴포넌트 `detective-app.tsx`, 통합 `screens.tsx`, `use-investigation.ts`를 기준으로 문서를 읽지 마세요. 현재는 원본 `case-app.tsx`, 화면별 파일, `use-case-game.ts`를 사용합니다.

## 2. 유지한 UI와 사용 흐름

- 원본 홈·사건 카드·준비 중 사건 안내
- 헤더·사이드바·메뉴·아이콘·반응형 배치
- 브리핑·오프닝 자동 표시·닫기·재생·재시청
- 장소 선택·검색·자료 카드·열람 팝업·이미지
- 증언자·진술 분류·원문·출처·타임라인 링크
- 심문 인물 선택·주제·자유 질문·증거 첨부·말풍선
- 쟁점·추론 출처 선택·기본/연쇄 추론·원본 근거 펼치기
- 시간대별 타임라인·수사 노트 디자인·700ms 자동 저장
- 최종 고발 선택·확정 팝업·결과·다시 수사
- 오류 토스트·팝업 포커스·Escape·Tab·이탈 경고

원본 CSS 7개와 layout은 그대로 유지합니다. 데이터 연결을 바꾸지 않아도 되는 지정 컴포넌트는 파일 자체의 바이트 동일성을 검사합니다. 모든 TypeScript 파일이 원본과 똑같다는 뜻은 아닙니다.

## 3. FastAPI로 대체한 처리

| 원래 화면이 필요로 하던 것 | 현재 공급·처리 경로                       |
| -------------------------- | ----------------------------------------- |
| 공개 사건·인물·질문 주제   | catalog                                   |
| 사건 카드 데이터           | catalog.application.cases                 |
| 자료 메타데이터·장소·검색  | catalog.display 및 views/evidence         |
| 최초 진술·질문/답변 검색   | views/testimonies                         |
| 실제 출처 분류·검색        | state.inferenceSources 및 views/inference |
| 획득 본문·증거 이미지      | 보호된 materials·evidence-assets          |
| 심문 승인 계획·대사·검증   | FastAPI 및 LangGraph                      |
| 추론 조합과 문서 생성      | inferences                                |
| 2차 조사·진행률·고발 준비  | FastAPI 계산과 state                      |
| 수사 기록·노트·최종 판정   | SQLite 및 변경 API                        |
| 결과의 정답 설명           | 종결 후 verdict.checkDetails              |

원본의 Next.js 게임 엔진, 파일 저장소, 숨겨진 정답·시나리오 판정은 프런트엔드로 복제하지 않습니다. 화면은 서버 결과를 표시하고 UI 초안·선택·배치만 관리합니다.

## 4. 연결을 위해 달라진 부분

첫 화면 전에 카탈로그 준비 단계가 추가됩니다. API 인증은 BFF와 HttpOnly 쿠키를 사용하며 변경 요청에는 UUID·revision이 붙습니다. 자동 저장과 심문은 같은 큐로 순서를 지킵니다. 원본 자산 주소는 Route Handler로 유지합니다.

안내 문구 중 ‘규칙 기반 데모’, ‘AI 서비스 미연결’, ‘Qwen·멀티 에이전트 미연결’ 부분은 실제 연결 구조를 설명하도록 변경했습니다. UI를 유지한다고 잘못된 미연결 설명까지 그대로 표시하지는 않습니다. 비교 검사는 이 연결 안내 차이를 명시적으로 맞춘 상태에서 진행합니다.

일반 실행에는 원본 폴더가 필요하지 않습니다. 다만 원본 소스 동일성 검사와 브라우저 원본 비교에는 `share_project`가 필요합니다.

## 5. 실제 모델과 fixture의 경계

실제 Qwen2.5-7B-Instruct·NF4 양자화·기존 LoRA 어댑터·LangGraph 구성은 백엔드 책임입니다. 프런트엔드는 해당 모델로 학습하지 않고 실행 모드도 임의로 바꾸지 않습니다.

fixture에서도 화면과 수사 저장은 같은 FastAPI 계약으로 검사할 수 있지만 실제 모델 품질·GPU 메모리·어댑터 호환성을 확인한 것은 아닙니다. `local` 모드 서버가 성공적으로 시작되고 실제 질문의 응답·모델 버전·진단 로그가 확인되어야 모델 경로를 검토할 수 있습니다.

## 6. 구현되지 않은 별도 기능

현재 회원 가입·계정별 여러 수사 목록·다른 기기 동기화·쿠키 만료 후 복구 UI·후속 사건 플레이·결제는 제공하지 않습니다. 준비 중 카드의 존재를 이런 기능의 완료로 해석하지 않습니다.

새 수사는 이전 DB 기록을 지우지 않고 새 게임과 쿠키를 발급합니다. 현재 UI는 그 이전 수사로 돌아가는 목록을 제공하지 않습니다.

## 7. 동일성 판단 기준

CSS·소스 비교, 동일 데이터의 브라우저 화면 비교, 실제 버튼 동작 검사를 함께 봅니다. 화면이 비슷하다는 인상만으로 API·저장까지 같다고 판단하지 않고, HTTP 성공만으로 원본 디자인이 유지됐다고 판단하지도 않습니다.

실제 확인 조건과 결과는 다음 [UI·UX 비교 검사](09_원본_UI_UX_유지와_비교검사.md)에 정리되어 있습니다.

## 현재 대화 보장 정책

원본 화면·쟁점 조건은 유지하면서, 기본 플레이의 유효 질문은 LLM 실패 시 승인 원문으로 복구합니다. 정보가 없는 질문도 중립 대사를 받습니다. UI가 답변을 직접 생성하거나 미승인 쟁점을 추가하는 변경은 아닙니다. [상세 정책](../../click_detective/docs/12_질문_응답과_복구_정책.md)
