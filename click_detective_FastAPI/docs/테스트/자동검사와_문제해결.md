## 기본 검사

프로젝트 가상환경을 활성화한 상태에서 실행한다.

```bash
cd click_detective_FastAPI
source .click_venv/bin/activate
python -m pytest -q
python -m ruff check app scripts tests
python -m ruff format --check app scripts tests
```

테스트는 명시적인 fixture 설정, 임시 MongoDB DB, 프로젝트 내부 사건 데이터를 사용한다. 실제 `.env`의 local 모드로 GPU 모델을 자동 로딩하지 않는다.

## 검증 에이전트 테스트 소요 시간

`click_detective_FastAPI`에서 실행하면 pytest가 케이스별 실행 시간을 터미널 하단에 표시한다. `call`은 테스트 본문, `setup`과 `teardown`은 각각 준비와 정리 단계의 시간이다. 이 테스트는 모의 모델을 사용한다.

```bash
python -m pytest -q tests/dialogue/validation_agent --durations=0 --durations-min=0
```

## 자동 검사 보고서

`tests/conftest.py`는 `.reports/pytest.json`에 결과를 기록한다. `passed`, `failed`, 검사별 `name`, `outcome`, HTTP 왕복 기록인 `exchanges`가 포함된다. `duration_seconds`는 준비와 정리 시간을 제외한 테스트 본문의 실행 시간(초)이며, 본문을 실행하지 못한 경우에는 `null`이다.

인증 키와 수사 토큰은 가린다. 질문·메모·응답은 보고서에 포함될 수 있다. HTTP 요청이 없는 규칙 검사에는 빈 왕복 목록이 있을 수 있다. 다시 실행하면 같은 파일을 갱신한다.

검증 에이전트 테스트에서는 `exchanges`에 그래프 요청 `input`과 최종 응답 또는 오류 `output`을 기록한다. `verification_exchanges`에는 재시도와 배치를 포함해 검증 모델에 전달한 메시지와 모의 모델이 돌려준 응답 원문이 호출 순서대로 들어간다.

## 모델 실행 진단

local 그래프는 기본적으로 `.data/dialogue-traces.jsonl`에 요청별 한 줄의 JSON을 기록한다. HTTP 요청의 `request_id`로 해당 실행을 찾는다.

| 이벤트 | 확인할 정보 |
|---|---|
| `preprocess` | 프롬프트 준비에 걸린 시간과 승인·필수 사실, 검증 문장 수 |
| `generation` | 생성 시도 번호와 소요 시간 |
| `generation_format` | 기대 출력 형식과 관찰한 외형 |
| `verification` | 배치별 보고서 요청 번호와 시간 |
| `candidate_rejected` | 후보 대사의 거절 코드 |
| `verification_rejected` | 보고서 형식·근거의 거절 코드 |
| `model_input`, `model_output` | 입력·출력 토큰 수와 제한 |
| `model_decoding` | 생성·검증 목적과 디코딩 옵션 |
| `model_resources` | 4비트·어댑터 적용 여부와 PyTorch 메모리 |

진단은 원문 질문·후보 대사·서비스 키를 저장하지 않는다. 최종 대사가 들어 있는 게임 DB, 실제 요청·응답을 저장하는 검사 보고서와 구분한다. PyTorch 메모리 값은 GPU 전체 시스템 사용량과도 구분한다.

## 자주 확인할 오류

| 상황 | 확인할 것 |
|---|---|
| API 401 | 서버와 호출 측의 서비스 키가 같은가 |
| 수사 API 404 | 해당 수사의 올바른 게임 토큰인가 |
| API 409 | 최신 revision·같은 UUID의 다른 본문·처리 중 중복·종결 여부 |
| API 422 | 입력값·허용 주제·자료 획득 조건·서버가 보고한 입력 한도 |
| API 429 | 수사 질문 한도를 모두 사용했는가 |
| strict 모드 502 | 모델·출력·검증 거절 코드와 `X-Generation-Error` |
| strict 모드 504 | 단계·전체 파이프라인 시간 초과 |
| 시작 시 모델 파일 오류 | 실제 모델·어댑터 경로와 준비된 파일 |
| 시작 시 CUDA 오류 | GPU·드라이버·모델 의존성 |
| 모델을 바꿔도 같은 응답 | 설정 변경 후 재시작 여부와 같은 request_id 재전송 여부 |

기본 복구가 허용되면 생성 실패가 HTTP 200 `fallback`으로 처리될 수 있다. 이것은 실제 모델 생성 성공인 `stop`과 다르다. 상세 조건은 [응답·복구 정책](../에이전트/응답과_복구_정책.md)을 참고한다.

실제 GPU 검사는 [실서버 LLM 검사](실서버_LLM_검사.md)를 따로 실행해야 한다.
