# 13. RAG 사실은 유지하고 대사 표현은 자유롭게 생성하기

[목차](README.md) · [멀티에이전트](05_LLM_양자화_멀티에이전트.md)

## 원하는 동작

RAG는 말할 수 있는 사실을 찾습니다. 그 원문을 답변으로 그대로 돌려줘야 한다는 뜻은 아닙니다. 생성 에이전트는 찾은 사실을 캐릭터의 대사로 새롭게 표현하고, 검증 에이전트는 표현이 달라도 사실의 의미가 유지되는지 검사합니다.

예를 들어 승인 사실이 “와인잔에 수면제 두 알을 넣었습니다. 병에는 넣지 않았습니다.”라면 “약을 넣은 건 병이 아니라 잔이었습니다. 수면제는 두 알이었어요.”처럼 어순과 문장을 바꿀 수 있습니다. **이 문장은 설명용 예시이며 실제 GPU 실행 결과가 아닙니다.** 세 알로 바꾸거나 병에도 넣었다고 말하는 것은 허용하지 않습니다. 승인되지 않은 감정이나 동기도 새로 만들지 않습니다.

## 기존 답변이 비슷했던 이유

기존 모델은 생성과 검증 모두 `do_sample=False`로 실행했습니다. 매 단계에서 가능성이 높은 토큰을 고르는 방식이라 원문과 비슷한 표현을 반복하기 쉽습니다. 프롬프트에서도 승인 원문과 필수 문장 목록이 강조돼 원문을 대본처럼 사용하기 쉬웠습니다.

검증 실패 시 `fallback`은 원래 정책상 승인 원문을 조립합니다. 승인 사실이 없는 `fixed`도 고정 답변입니다. 이 두 경로의 답변이 같은 것은 생성 샘플링으로 해결되는 문제가 아닙니다. 실제 표현 다양성은 `stop` 응답으로 평가합니다.

## 바뀐 처리 흐름

1. 전처리: 기존과 같이 승인 사실만 검색합니다. 공개 범위를 넓히지 않습니다.
2. 생성: 원문을 사실 자료로 읽고 어휘·어순·문장 분리/합치기·종결어미를 새롭게 구성합니다. 이 호출만 샘플링합니다.
3. 검증: 별도 greedy 호출로 의미를 확인합니다. 원문 복사나 글자 일치율을 요구하지 않습니다. 후보 문장 번호로 실제 근거를 선택합니다.
4. 확정: 의미·규칙·ID 검사를 통과한 대사를 저장합니다. 실패 시 제한된 재생성 또는 기존 복구 정책으로 처리합니다.

같은 모델 객체를 사용하지만 `generate(..., purpose="dialogue")`와 `generate(..., purpose="verification")`로 목적을 분리합니다. 외부 API의 입력 형식은 바뀌지 않습니다. NF4와 기존 어댑터 적용도 유지합니다.

## 표현 자유도 설정

실제 `.env`와 `.env.example`에 다음 설정을 추가했습니다.

```dotenv
CLICK_DIALOGUE_TEMPERATURE=0.65
CLICK_DIALOGUE_TOP_P=0.9
CLICK_DIALOGUE_REPETITION_PENALTY=1.05
```

| 설정 | 뜻 | 현재 기본값 |
| --- | --- | --- |
| temperature | 다음 토큰 선택의 다양성. 0이면 기존 greedy 방식 | 0.65 |
| top_p | 누적 확률로 다음 토큰 후보 범위를 제한 | 0.9 |
| repetition_penalty | 생성 중 반복을 약하게 억제. 원문과의 유사도를 측정하는 설정은 아님 | 1.05 |

검증에는 이 샘플링 설정을 전달하지 않고 `do_sample=False`를 사용합니다. 생성 자유도를 높인다고 원문 복사를 반드시 피하거나 품질이 반드시 좋아지는 것은 아닙니다. 너무 높은 자유도는 오히려 사실 변형과 fallback을 늘릴 수 있습니다. 프로세스 환경변수로 같은 설정을 지정했다면 `.env`보다 우선합니다.

## 검증에서 허용하는 것과 보존하는 것

동의어, 어순, 문장 길이, 종결어미, 단순 인사·연결어는 바꿀 수 있습니다. 필수 사실 전체의 의미, 행위자, 행동, 대상, 수량, 시간과 행동의 연결, 부정, 목격·전언·추측의 구분은 보존합니다.

“보지 못했다”를 “보았다”로 바꾸거나 “모르겠다”를 확정 진술로 바꾸면 안 됩니다. 의미 검증 외의 수량·시각·역할 역전 규칙도 유지합니다. 제한된 정규식은 일부 정상 동의어를 거절할 수 있으므로 실제 실패 로그를 보고 회귀 사례를 추가해야 합니다. 이번 변경으로 모든 동의어를 이해하게 된 것은 아닙니다.

문자열 유사도가 가장 높은 대사를 선택하는 방식은 쓰지 않습니다. 높은 유사도라도 수량이나 부정 하나가 다르면 사실이 달라질 수 있기 때문입니다. 반대로 완전히 같은 사실은 짧게 표현하면 원문과 비슷할 수 있으므로 최소 변경률을 강제하지도 않습니다.

## 적용과 확인

**현재 켜진 서버를 종료한 뒤 같은 가상환경으로 재시작해야 적용됩니다.** 같은 GPU에 두 번째 서버를 추가로 띄우지 않습니다.

```bash
cd ~/reverse/click_detective
.cd_venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

재시작 후 짧은 실서버 검사를 별도 보고서에 저장합니다.

```bash
.cd_venv/bin/python scripts/test_llm_api_live.py \
  --case profile \
  --trace-path .data/dialogue-traces.jsonl \
  --require-trace \
  --report .reports/llm-api-paraphrase-live.json
```

같은 질문을 새 수사에서 여러 번 실행해 `stop` 대사와 원문을 비교하세요. 같은 UUID를 재전송하면 기존 답변을 돌려주는 중복 처리 정책이 있으므로 다양성 평가용 새 생성이 아닙니다. 단일 응답만으로 다양성을 확인할 수는 없습니다.

새 진단의 `pipeline_version`은 `semantic-paraphrase-v7`입니다. `model_decoding` 이벤트에서 `purpose=dialogue`는 `do_sample=true`와 설정값을, `purpose=verification`은 `do_sample=false`를 기록합니다. temperature가 0일 때는 대사도 false입니다.

기존 130개 실서버 결과는 v6에서 실행한 과거 기록입니다. 이번 설정을 반영한 새 GPU 결과로 읽지 마세요. 이번 코드 회귀 검사는 실제 사건 데이터를 사용하되 모델 출력과 의미 판정은 모의 모델로 제공했습니다. 실제 GPU의 재서술 품질은 서버 재시작 후 별도 측정해야 합니다.
