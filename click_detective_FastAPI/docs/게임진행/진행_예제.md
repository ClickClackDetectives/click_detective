# 07. 게임 진행 예제로 이해하기

[목차](../README.md) · [전체 게임 검사 코드](../코드참조/tests/investigation/test_game_progress.md)

## 1. 시작과 복원

먼저 GET /v1/catalog에서 caseId와 scenarioVersion을 받습니다. 새 UUID로 POST /v1/games를 보내면 game_id·game_token·state를 받습니다. 이후 호출은 서비스 키와 게임 토큰을 함께 사용합니다.

새로고침 시에는 기존 game_id·game_token으로 GET /v1/games/{id}를 호출합니다. 재시작은 새 수사를 만드는 방식으로 처리합니다. 기존 수사를 같은 ID로 초기화하는 API는 없습니다.

## 2. 자료 목록과 열람

GET materials는 현재 단계의 공개 목록입니다. acquired=false인 원본은 제목·요약만 표시하고 POST examinations로 열람합니다. 그 뒤 material_key=evidence:ID로 상세를 조회합니다. 사진도 별도 증거 자산 API에서 획득 조건을 확인합니다.

GET으로 조회했다고 examined가 늘어나지 않습니다. 같은 원본 열람을 반복해 진행률을 올릴 수 없습니다.

## 3. 질문과 쟁점

사용자는 인물·질문·선택 자료·선택 주제를 보냅니다. 서버는 인물별 과거 제시 자료와 이번 자료를 합치고, 추론을 제시했다면 원본 leafSources를 펼쳐 조건을 검사합니다.

자료를 읽기만 한 것과 인물에게 제시한 것은 다릅니다. 다른 인물에게 제시한 자료도 섞지 않습니다. 새 쟁점은 이번에 자료를 제시했을 때, 필요한 자료가 모두 모였고 아직 발견하지 않은 경우에만 계획합니다.

검증된 생성(stop), 정보 없음의 중립 응답(fixed), 승인 원문 복구(fallback)가 정상 확정되면 질문 1회·질문/답변 2개·승인 계획의 구조화 진술과 쟁점을 함께 반영합니다. strict 생성 실패나 상태 충돌로 확정하지 못한 작업만 저장되지 않습니다. fixture는 승인 원문을 조립한 뒤 같은 게임 확정을 수행합니다.

## 4. 증언과 동선

movement 주제는 현재 인정 flag에 맞는 동선 후보를 선택합니다. about-다른인물ID는 관계 진술입니다. 명시적 주제가 잘못되면 422입니다.

자유 질문은 알려진 패턴에 한해서 동선·인정 진술로 연결합니다. 모든 자연어를 일반적인 의도 분류기로 이해하는 구현은 아닙니다. 연결할 승인 사실이 없으면 중립 답변입니다. 자기소개 프로필을 했다는 이유로 구조화 진술 개수를 늘리지는 않습니다.

## 5. 추론

추론은 실제 획득한 출처 2~4개를 선택합니다. 필요 출처가 정확히 일치해야 하며 순서는 달라도 되지만 불필요한 자료를 하나 더 선택하면 다른 조합입니다. 같은 출처의 중복은 허용하지 않습니다.

연쇄 추론은 실제 선행 derived 문서를 선택해야 합니다. 원본들을 모두 골랐다고 선행 추론을 선택한 것으로 바꾸지 않습니다. sourceRefs는 직접 선택한 자료, leafSources는 그 안의 최종 원본·진술 근거입니다.

같은 결론은 새 UUID로 다시 요청해도 개수를 늘리지 않습니다. 단, 코드상 추론의 조사 단계는 정확히 일치해야 하므로 1차 추론을 2차에서 다시 생성하려 하면 단계 오류가 날 수 있습니다.

## 6. 2차 조사

현재 사건은 추론 2개 이상·쟁점 2개 이상일 때 2차로 전환합니다. 서버는 phase를 2로 바꾸면서 자동 자료 2-03도 열람 목록에 넣습니다. 클라이언트가 phase=2를 상태에 직접 저장하는 방식은 아닙니다.

## 7. 진행도와 고발은 다릅니다

진행률은 원본 자료 29개 + 발견 쟁점 10개 + 추론 10개, 총 49개를 기준으로 계산합니다. 중복은 한 번만 계산하고 양수에 대한 JavaScript Math.round와 같은 방식으로 반올림합니다.

고발은 1차 조사부터 언제든 제출할 수 있습니다. 진행도·추론 개수·쟁점 개수 제한이 없고 추론 증거 0개도 허용합니다. 범인·동기·수단은 선택해야 하며, 근거 부족은 입증 평가에 반영합니다. 정답 후보 이름·필수 상세 목록을 정상 화면의 사전 정답 API로 노출하지 않습니다.

제출한 추론의 원본 근거가 핵심 그룹을 포함하는지 판정합니다. 범인·동기·수단·핵심 연결 네 검사를 각각 25점으로 채점합니다. 조건을 충족해 제출한 오답도 verdict를 만들고 종결될 수 있습니다. 종결 후 메모·심문 등 변경은 409입니다.

## 8. 전체 흐름을 코드로 확인하기

테스트 test_full_game_to_100_percent_and_correct_verdict는 API로만 원본 29개·쟁점 10개·추론 10개를 확보하고 100%·정답 100점까지 확인합니다. 이 테스트는 내부 정답 데이터를 사용하는 개발용 검사이며 브라우저가 정답 파일을 읽는 방식이 아닙니다.
