# API 인증과 요청 재시도

개발 주소 예시는 `http://127.0.0.1:8000`이다. `GET /healthz`는 인증 없이 호출한다. 업무 API에는 `Authorization: Bearer <CLICK_API_KEY>`를 보낸다. 이 키는 Next.js 서버와 FastAPI 사이에서 사용한다. 인증 실패는 401이며 `WWW-Authenticate: Bearer`를 반환한다. [서비스 인증](../../app/runtime/runtime_auth.py)

| 접근 방식 | 추가 헤더 |
| --- | --- |
| 공개 사건 조회 | 서비스 Bearer만 사용 |
| 익명 수사 조회·변경 | 해당 수사의 `X-Game-Token` |
| 계정 수사 조회·변경 | `X-Access-Token`. `X-Expected-User-Id`를 보냈다면 토큰의 계정과 일치해야 한다. |
| 계정 갱신 | `X-Refresh-Token` |
| 익명 수사를 계정에 연결 | 계정 토큰과 해당 익명 수사의 `X-Game-Token` |

## 새 요청과 재전송

새 수사는 `request_id`, 사건 ID와 버전을 보낸다. 기존 수사를 변경할 때는 최신 `state.revision`을 `expected_revision`으로 보낸다. 새 행동에는 새 UUID를 만들고, 네트워크 오류나 응답 유실로 같은 행동을 재전송할 때는 UUID와 본문을 유지한다. 이미 완료된 요청은 저장된 응답을 재사용한다.

기존 UUID에 다른 본문을 보내거나 이전 revision으로 새 행동을 보내면 충돌한다. 수사 생성은 `game_id`, `game_token`, `state`를 반환한다. 계정으로 생성한 수사의 `game_token`은 null이다. 상태 변경 응답은 `request_id`, `result`, `state`를 제공한다. [수사 저장과 예약](../서버/수사_저장.md)

## 오류 응답

| 상태 | 확인할 내용 |
| --- | --- |
| 401 | 서비스 키 또는 계정 세션 |
| 404 | 사건·자료 ID와 수사 접근 권한 |
| 409 | 사건 버전, revision, 진행 중인 요청과 요청 UUID |
| 422 | 필수 필드·형식·자료 열람 조건 |
| 429 | 질문 한도 또는 계정 요청 제한 |
| 502·504 | 대사 생성·검증 실패 또는 제한 시간 초과 |
| 503 | 수사 저장소 연결 또는 계정 기능·내부 그래프의 가용 상태 |

FastAPI 입력 검증 응답은 오류의 위치와 종류를 반환한다. 응답에는 `Cache-Control: no-store`가 적용된다. 심문 응답을 해석할 때는 HTTP 상태와 함께 `finish_reason`을 확인한다. [공통 오류 처리](../../app/main.py) · [심문 응답 정책](../에이전트/응답과_복구_정책.md) · [경로 목록](README.md)
