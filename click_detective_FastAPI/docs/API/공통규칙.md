## 주소와 인증

개발 서버 기본 예시는 `http://127.0.0.1:8000`이다. `GET /healthz`는 인증 없이 호출한다. 문서에서 다루는 나머지 업무 API에는 다음 헤더가 필요하다.

```text
Authorization: Bearer <CLICK_API_KEY>
```

수사별 API에는 해당 수사 생성 응답의 `game_token`을 추가한다.

```text
X-Game-Token: <game_token>
```

서비스 키와 게임 토큰은 서로 다른 값이다. [authenticate](../../app/dependencies.py)는 서비스 키를 확인하고, 저장소는 수사 토큰으로 소유권을 확인한다.

## 생성·변경 요청

새 수사는 `request_id`, 사건 ID와 사건 버전을 보낸다. 기존 수사를 바꾸는 행동은 `request_id`와 `expected_revision`을 공통으로 보낸다. 행동별 추가 필드는 [각 API](상세/README.md)에서 확인한다.

- `request_id`: 새 행동에는 새 UUID, 같은 행동 재전송에는 같은 UUID와 본문
- `expected_revision`: 직전에 조회하거나 변경한 응답의 최신 `state.revision`

완료된 동일 요청은 캐시된 응답을 재사용한다. 동일 UUID로 다른 내용을 보내거나 처리 중인 작업을 중복 실행하면 거절한다. 생성 중 다른 행동이 먼저 상태를 바꾸면 오래된 결과의 저장도 거절한다.

정의하지 않은 JSON 필드는 거절한다. 승인 사실·획득 상태·정답은 사용자 행동 입력으로 직접 지정하지 않는다.

## 응답 모양

수사 생성은 `game_id`, `game_token`, 공개 `state`를 돌려준다. 상태 변경은 다음과 같은 공통 구조를 사용한다.

```json
{
  "request_id": "이번 요청 UUID",
  "result": {"행동별": "결과"},
  "state": {"revision": 1}
}
```

위 예시는 구조 설명용으로 state와 result를 줄였다. GET 응답은 경로별로 `materials`, `findings`, `state` 등 반환 필드가 다르다.

심문 결과의 `finish_reason`은 `stop`, `fixed`, `fallback`을 구분한다. 성공한 복구 응답도 질문과 대화로 확정한다. [응답·복구 정책](../에이전트/응답과_복구_정책.md)

## 주요 상태 코드

| 코드 | 대표 원인 |
|---|---|
| 200 | 조회 또는 행동 정상 처리. 심문의 fallback도 포함 가능 |
| 401 | 서비스 키 누락·불일치 |
| 404 | 없는 사건·자료 또는 올바른 토큰으로 접근할 수 없는 수사 |
| 409 | 사건·상태 버전 충돌, 동일 UUID의 다른 내용, 처리 중 중복, 종결 등 |
| 422 | 입력 형식·주제·자료 획득·출처 조합 등의 조건 오류 |
| 429 | 질문 한도 초과 |
| 502 | 복구 비허용 시 생성·검증 실패 등 |
| 504 | 복구 비허용 시 생성·검증 시간 초과 |

경로별 예외는 상세 문서를 따른다. 입력 검증 오류는 원문·토큰 대신 위치와 오류 종류만 공개한다. 응답에는 `Cache-Control: no-store`를 적용한다.
