# 공용 로컬 모델

[에이전트 목차](README.md) · [생성 에이전트](생성/README.md) · [검증 에이전트](검증/README.md)

대화 provider는 local에서 모델을 앱 수명당 한 번 로딩한다. 생성과 의미 검증은 동일 모델을 호출하며 목적별 디코딩 옵션과 실행 잠금을 사용한다.

## 모델을 준비하는 시점

`bootstrap.lifespan`은 local 모드에서 `LocalQwenModel` 객체를 만들고 `load`로 모델을 불러온다. 모델을 그래프에 전달하고 생성·검증 단계가 같은 객체를 사용한다. 요청마다 가중치를 다시 읽지 않는다.

[서버 시작](../../app/runtime/runtime_lifespan.py) · [모델 코드](../../app/dialogue/services/model/dialogue_local_model.py)

## 파일 검사와 로딩

`model_loading.validate_model_files`는 모델 설정·토크나이저 설정·가중치와, 설정된 어댑터의 설정·가중치가 존재하는지 확인한다.

`load_model`은 CUDA가 준비되어 있는지 확인하고 bitsandbytes의 4비트 NF4와 double quantization을 적용해 모델을 불러온다. 연산 자료형은 GPU에 따라 BF16 또는 FP16이다. 기본 모델에 4비트 로딩이 적용되었는지 확인하고, 어댑터 경로가 있으면 PEFT로 기존 어댑터를 불러온다.

[로딩 코드](../../app/dialogue/services/model/dialogue_model_loading.py)

로컬 파일만 사용하며 모델을 자동 다운로드하거나 새로 학습하지 않는다. 양자화는 로딩 과정에서 적용하며 원본 가중치 파일을 덮어쓰는 작업은 아니다. QLoRA는 학습 방식이고, 여기서는 기존 어댑터를 추론에 사용하는 역할을 구분한다.

## 모델 호출 목적

| 목적 | 호출 | 기본 디코딩 |
|---|---|---|
| 대사 작성 | `generate(..., purpose="dialogue")` | 샘플링. 온도가 0이면 greedy |
| 의미 검사 | `generate(..., purpose="verification")` | greedy |

`decoding_options`는 목적에 따라 실행 옵션을 만든다. 생성 자유도가 검증 JSON에 적용되지 않는다.

## 실제 실행 순서

1. `LocalQwenModel.generate`가 공용 잠금을 획득한다.
2. 별도 스레드에서 `_generate_sync`를 실행한다.
3. 채팅 템플릿을 적용하고 입력 토큰 수를 검사한다.
4. 모델을 실행하고 입력 부분을 제외한 생성 결과만 디코딩한다.
5. 실제 추론이 끝나면 잠금을 해제한다.

요청이 취소되거나 시간 제한을 넘었다고 이미 시작한 GPU 연산이 즉시 멈추는 것은 아니다. 실행 중인 작업이 끝나기 전에 잠금을 풀지 않아 다음 호출이 같은 모델에서 겹치지 않게 한다.

입력 한도를 넘으면 필수 사실을 조용히 잘라내지 않고 `ModelContextError`로 알린다. 그래프와 서비스가 복구 설정에 따라 처리한다.

## 확인할 수 있는 것과 없는 것

진단의 `model_resources`에는 4비트 적용 여부, 양자화 이름, 어댑터 사용 여부와 PyTorch 메모리 값 등이 기록된다. HTTP 응답의 모델 이름만으로 실제 가중치 양자화나 GPU 제품명을 증명할 수는 없다.

fixture·모의 모델 테스트와 실제 GPU 실행은 [테스트 안내](../테스트/README.md)에서 구분한다.
