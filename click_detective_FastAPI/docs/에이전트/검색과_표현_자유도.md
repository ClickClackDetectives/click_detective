# 검색과 대사 표현 자유도

[에이전트 목차](README.md) · [전처리](전처리/README.md) · [생성](생성/README.md) · [검증](검증/README.md)

검색 설정은 질문에 맞는 승인 진술을 고르는 데 사용한다. 생성 샘플링은 선택된 진술을 표현하는 문장의 다양성에 영향을 준다.

## 검색은 사용할 사실을 고르는 작업이다

E5는 현재 인물과 공개 쟁점으로 한정한 질문 후보의 코사인 유사도를 비교한다. 개별 동선과 인정 진술은 제목·시각·본문을 한 문자열로 임베딩한다. 질문에 정확한 시각이 있으면 후보의 기록 시각과 대조한다.

`rag_top_k`는 자유 질문에서 선택할 개별 진술 수를 제한한다. 전체 동선은 묶음 하나로 선택한다. `GameService.dialogue_request`는 선택한 원문을 모두 필수 사실로 지정하고 전처리 에이전트가 그 순서로 생성 프롬프트에 담는다.

## 사실을 보존하면서 문장은 바꿀 수 있다

승인 사실이 “22시 40분에 흰 장갑을 낀 사람을 보았습니다. 얼굴은 확인하지 못했습니다.”라고 가정하자. 생성 에이전트는 어휘와 말투를 바꿀 수 있지만, 시각·행동·관찰 한계는 유지해야 한다.

이 예시는 동작 설명용이며 실제 사건 원문이나 GPU 생성 결과의 인용이 아니다. 등장인물의 이름을 새로 단정하거나 “얼굴을 보았다”고 바꾸면 승인 의미를 벗어난다.

검증은 원문 문자열을 그대로 복사했는지보다 의미가 보존되었는지 확인한다. 별도 모델 판정과 수량·시각·행위자 등 제한된 규칙을 함께 사용한다. 모든 동의어나 의미 변형을 완벽하게 이해한다는 뜻은 아니다.

## 생성과 검증의 디코딩

| 설정 | 기본값 | 적용 |
|---|---|---|
| `dialogue_temperature` | 0.65 | 생성의 표현 다양성 |
| `dialogue_top_p` | 0.9 | 생성 후보의 누적 확률 범위 |
| `dialogue_repetition_penalty` | 1.05 | 생성 표현의 반복 억제 |

생성만 샘플링하며 검증은 greedy 방식이다. 온도가 0이면 생성도 샘플링하지 않는다. 자유도를 높인다고 새 사실을 추가할 권한이 생기거나 표현 다양성·품질이 반드시 좋아지지는 않는다.

## 비슷한 답변을 읽는 방법

- `fixed`는 중립·fixture 고정 대사다.
- `fallback`은 승인 원문을 연결한 복구 대사다.
- `stop`이 모델 생성·검증을 통과한 대사다.
- `partial`과 `neutral`은 검증된 일부 정보 또는 중립 안내를 제공한다.

표현 다양성은 `stop` 응답을 비교해야 한다. 같은 UUID와 본문을 재전송하면 이전 응답을 재사용하므로 새 생성이 아니다. 새로운 독립 수사에서 같은 질문을 비교하고, 단일 응답만으로 다양성을 판단하지 않는다.

## 설정 적용과 진단

`.env` 또는 환경변수를 바꾼 뒤 서버를 재시작한다. 같은 이름의 프로세스 환경변수는 `.env`보다 우선한다. `model_decoding` 이벤트의 목적과 `do_sample` 값을 확인한다.

현재 진단 버전은 코드의 `PIPELINE_VERSION`을 기준으로 읽는다. 과거 보고서의 버전이 다르면 최신 코드로 재실행한 결과와 구분한다. 실제 표현·검증 품질은 [실서버 검사](../테스트/실서버_LLM_검사.md)로 별도 확인한다.
