# 심문 응답·실패 복구·저장

수사 서비스가 질문을 승인한 뒤 대화 서비스가 대사를 준비한다. 쟁점이 없어도 심문은 진행할 수 있다. 쟁점·출처·열람 조건은 수사 규칙과 승인 계획이 결정한다. [승인 계획](../../app/investigation/services/interrogation/investigation_interrogation_planner.py)

| `finish_reason` | 결과 |
| --- | --- |
| `stop` | 생성한 대사가 해당 버전의 검증을 통과했다. |
| `fixed` | fixture 또는 고정 대사가 반환됐다. |
| `fallback` | 생성·검증 실패 후 승인된 원문으로 응답을 조립했다. |
| `partial` | 검증에서 전달 가능한 사실만 반환했다. |
| `neutral` | 검증에서 질문에 중립 답변을 반환했다. |

`CLICK_FALLBACK_ON_ERROR=false`는 대화 서비스에서 재전파하는 실패를 관찰할 때 사용한다. 서비스 수준의 복구가 허용되면 중립 응답을 사용한다. 검색이 승인 계획을 확정하기 전에 실패하면 해당 검색 결과로 복구하지 못한다. [대화 서비스](../../app/dialogue/services/reply/dialogue_reply_service.py) · [생성 결과 검증](../../app/dialogue/services/reply/dialogue_reply_validation.py)

## 질문 차감과 결과 확정

유효한 심문은 접수할 때 질문을 한 번 차감한다. 정상 확정된 답변은 대화에 추가된다. 생성에 실패해도 이미 접수한 심문의 차감은 유지된다. 같은 요청을 재전송할 때는 동일한 UUID와 본문을 사용한다. 인물·자료·수사 상태가 접수 조건에 맞지 않으면 접수 전에 거절한다.

최종 저장 전에 예약 실행권과 기준 revision을 확인한다. 처리 중 상태나 소유권이 바뀌면 기존 결과를 그 위에 덮어쓰지 않는다. 실패하면 해당 실행이 보유한 예약만 정리한다. [수사 상태와 트랜잭션](../서버/수사_저장.md) · [심문 API](../API/상세/13_interrogate.md)
