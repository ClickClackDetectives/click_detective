# 프로젝트 소개

[전체 목차](../README.md) · 다음: [설치와 실행](02_설치와_실행.md)

Click Detective는 증거를 열람하고 인물에게 질문하며 사건을 해결하는 추리 게임이다. 이 FastAPI 프로젝트는 사건 데이터, 게임 규칙, 수사 기록 저장과 AI 대사 생성을 담당한다. 화면은 `click_detective_Next_js`가 담당한다.

## 먼저 알아둘 용어

| 용어 | 쉬운 설명 |
|---|---|
| 서버 | 질문을 받아 실제 작업을 처리하는 프로그램 |
| API | 화면 프로그램이 서버에 작업을 요청하는 약속된 창구 |
| 클래스 | 관련 정보와 기능을 묶어 놓은 코드 단위 |
| 함수·메서드 | 이름이 붙은 작업. 클래스 안의 함수는 메서드라고 부른다 |
| 에이전트 | 여기서는 전처리·생성·검증 중 하나를 맡은 처리 단계 |
| 프롬프트 | AI에게 전달할 지시와 참고 자료 |
| 승인 사실 | 현재 질문에서 말해도 된다고 게임 규칙이 선택한 진술 |
| revision | 저장된 수사 상태의 버전. 다른 요청이 먼저 상태를 바꾸었는지 확인할 때 사용 |
| fallback | 모델 생성·검증 실패 후 승인 원문으로 만드는 복구 대사 |

승인 사실은 공개 권한을 뜻한다. 인물의 진술이 사건의 객관적인 진실임을 보증한다는 뜻은 아니다.

## 서버가 하는 일

1. 사건·인물·공개 자산을 조회한다.
2. 증거 열람과 심문으로 진술·쟁점을 기록한다.
3. 획득한 출처의 정해진 조합으로 추론을 만든다.
4. 조사 단계를 바꾸고 고발을 채점한다.
5. 수사 상태와 메모를 SQLite에 저장한다.
6. 공개가 승인된 사실을 AI 인물 대사로 표현하고 검사한다.

공개 사실 선택과 정답 판정은 Python 게임 규칙이 담당한다. AI는 대사를 생성하고 의미 보존 여부를 검사한다.

## 실행 모드는 두 가지다

| 모드 | 동작 | 필요한 준비 |
|---|---|---|
| `fixture` | 승인 원문을 연결한 고정 대사 | 기본·테스트 의존성 |
| `local` | 실제 모델로 생성·검증 | 로컬 모델 파일, 설정된 호환 어댑터, CUDA GPU와 모델 의존성 |

처음에는 fixture로 API·게임 진행·저장을 확인한 뒤 local을 준비하면 된다. 모델 파일은 서버가 자동으로 다운로드하거나 새로 학습하지 않는다.

## 코드의 큰 구분

- `app/cases`: 사건 파일과 공개 카탈로그
- `app/investigation`: 수사 행동, 기록, 저장과 화면 정보
- `app/dialogue/preprocess_agent`: 승인 사실 선택과 입력 준비
- `app/dialogue/inference_agent`: 후보 대사 생성
- `app/dialogue/validation_agent_v1`: 형식·의미 검사와 재생성 판단

상세한 폴더 트리는 [코드 읽는 순서](04_코드_읽는_순서.md)에서 확인한다.
