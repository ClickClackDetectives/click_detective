# Python 코드 읽는 순서

앱 시작은 `app/main.py`에서 `app/runtime/`으로 이어진다. runtime은 공용 설정과 서비스 인증을 제공하고, lifespan은 각 도메인의 provider를 호출한다. [진입점](../../app/main.py) · [lifespan](../../app/runtime/runtime_lifespan.py)

| 위치 | 맡은 일 | 먼저 읽을 파일 |
| --- | --- | --- |
| `runtime/` | 환경 설정, 서비스 인증, 앱 수명 | [runtime_lifespan.py](../../app/runtime/runtime_lifespan.py) |
| `auth/` | 계정·세션·탈퇴 및 PostgreSQL 저장 | [auth_service.py](../../app/auth/services/auth_service.py) |
| `cases/` | 사건 원본·버전·공개 카탈로그 | [cases_catalog_service.py](../../app/cases/services/cases_catalog_service.py) |
| `dialogue/` | 승인 문맥의 검색·대사 생성·검증 | [dialogue_reply_service.py](../../app/dialogue/services/reply/dialogue_reply_service.py) |
| `investigation/` | 수사 규칙·승인 계획·MongoDB 상태 변경 | [investigation_game_service.py](../../app/investigation/services/investigation_game_service.py) |

업무 도메인 네 곳은 같은 구조를 사용한다.

- `controllers/`는 HTTP 입력과 인증 문맥을 읽고 응답을 만든다.
- `services/`는 유스케이스와 도메인 규칙을 실행한다.
- `dto/`는 요청·응답과 서비스 사이에 전달할 데이터를 정의한다.
- `repositories/`는 DB, 파일, 검색 인덱스와 연결한다.
- `providers/`는 객체를 조립해 앱 시작과 요청에 제공한다.

## 요청으로 따라가기

- 공개 카탈로그는 [사건 컨트롤러](../../app/cases/controllers/cases_controller.py) → [사건 서비스](../../app/cases/services/cases_catalog_service.py) → [파일 저장소](../../app/cases/repositories/cases_file_repository.py)로 이어진다.
- 심문은 [수사 컨트롤러](../../app/investigation/controllers/investigation_game_controller.py) → [수사 서비스](../../app/investigation/services/investigation_game_service.py) → [심문 계획](../../app/investigation/services/interrogation/investigation_interrogation_planner.py) → [대화 그래프](../../app/dialogue/services/reply/dialogue_interrogation_graph.py) → [MongoDB 저장소](../../app/investigation/repositories/investigation_mongo_repository.py) 순으로 따라간다.
- 로그인은 [인증 컨트롤러](../../app/auth/controllers/auth_controller.py) → [인증 서비스](../../app/auth/services/auth_service.py) → [PostgreSQL 저장소](../../app/auth/repositories/auth_repository.py)로 이어진다.
